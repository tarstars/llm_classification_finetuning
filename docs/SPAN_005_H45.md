# H45: inferred strength has a small signal; primary selection does not improve

H45 completed its predeclared experiment. **The adoption gate failed.** On the
same 5,746 development rows / 5,211 prompt groups, the primary nested selector
gives loss **0.953834**, versus matched LoRA calibration **0.953701**: gain
**−0.000133**, paired 95% interval **[−0.002038, 0.001660]**. No submission or
promotion follows from this result.

| Method | Log loss | Gain versus matched LoRA calibration | Paired 95% interval |

| Style control | 0.954809 | −0.001108 | See aggregate |
| Inferred strength, fixed family | 0.952397 | +0.001305 | [0.000037, 0.002618] |

| Shuffled-source control | 0.953985 | −0.000283 | [−0.000749, 0.000197] |

The compact strength family is promising, but selecting it now after inspecting
both outer results would change the primary procedure. The inner selector chose
the full posterior family in fold 0 and strength in the other four folds; this
choice erased the small fixed-family advantage. Family-selection variability is
a plausible limitation, not proof that any future strength-only model will win.
The next step is a frozen replication on a separately scored cohort, not dropping
the unfavorable selection result or retuning on the leaderboard.

Practical source-only preference loss is 1.077106, accuracy 41.99%. The primary
combined model has 54.11% accuracy versus calibration's 53.88%, despite its slightly
worse log loss. Accuracy alone therefore does not establish an improvement.
The known-name oracle diagnostic at 0.940456 remains separate: most of its benefit
was not recovered by the inferred-source pipeline. Source-class accuracy is also
not preference accuracy.

The practical worker loads prompt/response text, IDs for alignment, and inferred
posteriors; it does not load development model-name columns. Source and strength
models stay frozen from original training. All residual/calibration/regularization
and family selection uses inner groups within each outer training fold, with the
same outer folds and matched calibration/style controls as E06. The shuffled
control uses a fixed label-independent permutation. All swap checks pass.
Original human votes remain unchanged; confirmation was not evaluated. Results
remain exploratory because development/checkpoint selection were inspected.

H45 took **24.705 seconds** of CPU experiment elapsed time, peak RSS **0.459 GiB**.
Its admitted setup-inclusive conditional runtime projection is 19,245.25 seconds,
using the prior classifier rate and local source CPU speed. This is not an actual
new Kaggle end-to-end profile. GPU use and new submissions are zero.

**Decision:** done, primary result inconclusive/slightly negative; preserve the
positive fixed-family diagnostic and queue a frozen follow-up. Keep official
score 0.95481 as the deployment reference.
