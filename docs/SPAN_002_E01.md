# E01: accepted-update and exposure measurement

The actual two-T4 CUDA probe completed successfully in Kaggle notebook
`arseniytrushin/llm-preference-span-002-exposure-probe/1`. Both rank artifacts,
parameter-change checks, scaler/scheduler state and source hashes are preserved in
[aggregate results](../results/span_002/instrumentation_results.json) and the private
job output under `~/database/llm_classification_finetuning/runs/span_002/`.

The tiny Trainer experiment ran five nominal cycles with one intentional gradient
overflow at cycle two. On each rank:

- Exactly four updates were accepted and one skipped.
- Every accepted update changed parameters; the skipped update changed none.
- All resulting parameters were finite, and the scheduler advanced four times.
- Twenty local rows / 80 tokens were processed, versus 16 rows / 64 tokens accepted.
- Resuming from checkpoint three reproduced final parameters within the declared
  tight numerical tolerance and exactly reproduced row/token/class counters,
  scaler state and scheduler state.

Notebook session time was **55.02 seconds**, within the 900-second allocation.
Quota increased **69.986 seconds** before the next job's launch; later quota
snapshots include concurrent judge use and must not be assigned entirely to E01.

blend endpoints and exposure counter persistence/scheduler mismatch rejection.

and per-cycle logs stay private. Checkpoints store per-rank audit counters at an
