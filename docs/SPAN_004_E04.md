# E04: disabling prompt reuse does not establish native repeatability

The bounded diagnostic is complete with a **negative stability result**.
Both cache settings produce materially different probabilities for identical
prepared token inputs. No configuration qualifies for uniform fitting-cache
rescoring or H44. Disabling KV prompt reuse alone does not fix the problem;
batch/concurrency sensitivity remains an untested hypothesis, not a proven cause.

## Actual comparison

The same 64 known development rows/64 groups were scored eight times: initial,
repeat, fixed permutation and clean-server restart for cache_on and cache_off.
Only the completion cache_prompt boolean differs between configurations. Two
server processes share the unchanged16-slot settings. There are ** 512 fresh
competition requests plus 12 synthetic preflight decisions**. Competition winner
columns were not read on the GPU. Every pass used a new checkpoint directory.

All512 raw response vectors were independently reconstructed, hashes verified,
and aligned by exact IDs. Prepared token IDs match across every case/pass,
including BOS/template/truncation. The fixed raw guards are mean<=0.001 and
maximum<=0.01. Every comparison fails:

| Cache | Comparison with its initial pass | Mean absolute drift | Maximum drift | Argmax changes |
| --- | --- | ---: | ---: | ---: |
| on | same order repeat | 0.018796 | 0.170790 | 0/64 |
| on | permuted order | 0.021524 | 0.202364 | 2/64 |
| on | clean restart | 0.023221 | 0.328158 | 3/64 |
| off | same order repeat | 0.020813 | 0.243951 | 2/64 |
| off | permuted order | 0.027951 | 0.237268 | 2/64 |
| off | clean restart | 0.025487 | 0.208597 | 2/64 |

Even an unchanged argmax can hide a large probability change, which matters for
log loss and calibration. Both cases also fail the separate historical-cache
identity requirement. Neither numerical tolerance was relaxed, and no raw cache
was replaced or mixed into a new blend.

## Runtime and diagnostic quality

The conservative observed judge rates are1.19279s/row with reuse and 0.884327s/row
without reuse. Using the frozen classifier rate,25,000 assumed hidden rows,
20%routed,20%inference margin,600 seconds reserve and395.91 seconds measured setup
allowance gives **26,328.60s** versus **24,477.82s**. The latter passes the
25,200-second projection guard but fails numerical stability. These remain
conditional projections, not a measured end-to-end submission runtime. Cache_off
always ran second in each process, so the observed speed difference is not a
counterbalanced causal estimate of the cache flag's effect.

Raw judge log loss ranges1.38055–1.42668 across passes. Applying the unchanged
frozen2,048-row judge calibrator gives0.97126–0.98064. Every fixed-calibration
loss-effect interval against the historical H37 sentinel includes zero. These 64
rows were already inside that calibrator's fitting cohort: this is a numerical
diagnostic, not independent validation or a setting-selection criterion. All
class losses, recalls, discrimination and confusion matrices are retained in the
aggregate results. The matched classifier and training-prior/majority/uniform
controls are reported separately. No parameter was fitted from these new scores.

Model source is immutable Gemma4-26B-A4B-IT QAT Q4_0 version 2. Before inference,
the 14,439,361,440-byte GGUF was hashed to
`4c856523d61d77922dbc0b26753a6bf6208e5d69d80db0c04dcd776832d054c5`.
The 175-file portable runtime manifest matches the earlier artifact semantically;
licenses, native CUDA0/CUDA1, resolved dependencies and actual two-device use pass.
Sampled device-used peaks are **9,551/8,833MiB**, including driver/runtime memory,
not allocator peaks. Packed token counts are identical across all passes;
native scoring remains single-order, with no both-order invariance claim.
